ใส่ข้อมูลตัวอย่างลง Firestore

กดปุ่มด้านล่างเพื่อเขียนผู้ใช้ 3 คน ประเภทการลา 3 แบบ ใบขอลา 5 ใบ และความเห็นการอนุมัติ 4 รายการ ลงฐานข้อมูลจริง — ใช้ id ที่ตายตัว (เช่น u001, lr001) จึงกดซ้ำกี่ครั้งก็ได้โดยไม่เกิดข้อมูลซ้ำซ้อน

1. ระบุ uid จริงของทั้ง 3 บทบาท

เดิมข้อมูลตัวอย่างใช้รหัสสมมติ u001 / u002 / u003 ซึ่งไม่ตรงกับ uid จริงที่ Firebase Authentication ออกให้ตอนสมัครสมาชิก ทำให้ใบลาที่ seed ไว้ ไม่ผูกกับบัญชีใครเลย และเปิดดูไม่ได้เมื่อบังคับใช้ Security Rules
ให้สมัครบัญชีจากหน้า สมัครสมาชิก ก่อน แล้วคัดลอก uid ของแต่ละบัญชีมาวางที่นี่ (ดู uid ได้ที่ Firebase Console → Authentication → คอลัมน์ User UID)

uid ของบัญชีที่ล็อกอินอยู่ตอนนี้: — ยังไม่ได้ล็อกอิน —

ถ้ามีบัญชีเดียว กดปุ่มด้านบนได้ — ข้อมูลตัวอย่างจะเป็นของคุณคนเดียวทั้งหมด เหมาะกับการลองเล่นคนเดียว แต่จะสาธิตการแบ่งสิทธิ์ 3 บทบาทไม่ได้

2. ใส่ข้อมูล

⚠️ ต้องรันตอนที่ Firestore ยังเปิดให้เขียนได้ — เช่นช่วงที่ยังเป็น Test mode หรือก่อนกด Publish กฎจาก firestore.rules ขึ้น Console เพราะกฎชุดนั้นตั้งใจห้ามไม่ให้ใครสร้างเอกสารผู้ใช้ของคนอื่น สร้างใบลาแทนคนอื่น หรือสร้างใบลาที่อนุมัติแล้วตั้งแต่ต้น ซึ่งเป็นสิ่งที่การ seed ต้องทำทั้งหมด
นี่คือพฤติกรรมที่ถูกต้องของกฎ — อย่าผ่อนกฎเพื่อให้ seed ผ่าน

ชื่อคนทุกชื่อในข้อมูลตัวอย่างเป็นชื่อสมมติ และอีเมลทุกตัวเป็นอีเมลตัวอย่าง ไม่ใช่ข้อมูลจริง
