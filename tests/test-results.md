### ⏭️ เคสที่ 1 — ยื่นใบลาใหม่แล้วไปโผล่ในหน้ารายการ

`tests/e2e/01-submit-leave-request.spec.js` · 9 ขั้น · อ้างเกณฑ์ **US-02 + US-01** (และ US-10 เรื่องลำดับ)

**ทดสอบอะไร** — ล็อกอินเป็น employee จดรายการเดิมไว้ กรอกฟอร์มยื่นใบลาใหม่ แล้วตรวจว่า
ใบนั้นโผล่ **บนสุด** ของตาราง มีป้าย "รอพิจารณา" ผู้ขอลาแสดงเป็นชื่อไทย คลิกเข้าไปแล้วค่าตรงทุกช่อง
และ **ยังอยู่หลังกด F5 ทั้งหน้ารายละเอียดและหน้ารายการ**

**ติดตรงไหน** — ข้ามตั้งแต่ก่อนเริ่มขั้น 1 เพราะไม่มีรหัสผ่านของบัญชี `somchai@example.com`

### ⏭️ เคสที่ 2 — กดอนุมัติแล้วสถานะเปลี่ยนจริง

`tests/e2e/02-approve-leave-request.spec.js` · 8 ขั้น · อ้างเกณฑ์ **US-04**

**ทดสอบอะไร** — ล็อกอินเป็น manager จด snapshot ทุกช่องไว้ กดอนุมัติ แล้วตรวจ 3 เรื่อง
1. สถานะลง Firestore จริง ไม่ใช่เปลี่ยนแค่บนหน้าจอ (พิสูจน์ด้วย F5 + เปิดจากแท็บที่สอง)
2. ปุ่มอนุมัติ/ไม่อนุมัติ **ยังกดไม่ได้หลังโหลดหน้าใหม่** ไม่ใช่ปิดแค่ตอนคลิก
3. **ช่องอื่นไม่ถูกเขียนทับ** เทียบ snapshot ก่อน–หลังทีละช่องแบบตัวอักษรต่อตัวอักษร
ปิดท้ายด้วยการล็อกอินเป็น employee แล้วตรวจว่ากดอนุมัติไม่ได้

**ขอบเขต** — ครอบเฉพาะทาง "อนุมัติ" ไม่ได้ทดสอบทาง "ไม่อนุมัติ"

**ติดตรงไหน** — ข้ามก่อนเริ่มขั้น 1 เพราะไม่มีรหัสผ่านของ `somying@example.com` และ `somchai@example.com`

### ⏭️ เคสที่ 3 — เว้นช่องหัวข้อแล้วกดบันทึก

`tests/e2e/03-empty-title-validation.spec.js` · 6 ขั้น · **นอกเหนือเกณฑ์ที่สเปกเขียนไว้**

**ทดสอบอะไร** — กรอกฟอร์มครบทุกช่องยกเว้นหัวข้อ แล้วกดบันทึก ต้องได้ 3 อย่าง
1. ขึ้นข้อความเตือนภาษาไทย
2. ยังอยู่หน้าเดิม ไม่เด้งไปหน้ารายการ
3. **จำนวนแถวในหน้ารายการเท่าเดิม** — ข้อนี้คือตัวจริงที่พิสูจน์ว่าไม่ได้บันทึก

เกณฑ์ US-02 ไม่ได้เขียนข้อนี้ไว้ แต่โค้ดตรวจให้อยู่แล้วที่ `js/new-leave-request.js:61`
เทสต์นี้จึงเป็นการล็อกพฤติกรรมที่มีอยู่ ไม่ให้หายไปตอนแก้โค้ดรอบหลัง

**ติดตรงไหน** — ข้ามก่อนเริ่มขั้น 1 เพราะไม่มีรหัสผ่านของ `somchai@example.com`

### ⏭️ เคสที่ 5 — เปิดใบลาของผู้ขอลาอีกคนไม่ได้

`tests/e2e/05-cannot-open-other-user-request.spec.js` · 6 ขั้น · อ้างเกณฑ์ **US-08**

**ทดสอบอะไร** — ล็อกอินเป็น employee คนแรก หาใบลาของตัวเอง ออกจากระบบ
ล็อกอินเป็น employee **อีกคน** แล้วเปิด URL ใบของคนแรกตรง ๆ ตรวจ 3 ชั้น
1. หน้าจอต้องไม่แสดงหัวข้อใบลาของคนแรก
2. อ่านเอกสารใบลานั้นด้วย ID token ของคนที่สอง ต้องได้ `PERMISSION_DENIED`
3. อ่าน subcollection `approvals` ของใบนั้น ต้องถูกปฏิเสธด้วย

ใช้ manager หรือ hr เป็นคนที่สองไม่ได้ เพราะสองบทบาทนั้นเปิดใบลาทุกใบได้ตามการออกแบบ

**ติดตรงไหน** — ข้ามก่อนเริ่มขั้น 1 เพราะไม่มีรหัสผ่านของ `somchai@example.com` และ `employee2@example.com`

## วิธีปลดล็อก 4 เคสที่เหลือ

```bash
cp tests/e2e/.env.example tests/e2e/.env.local
```

เปิด `tests/e2e/.env.local` แล้วเติมรหัสผ่าน 3 บรรทัด (อีเมลกรอกไว้ให้แล้ว)

```
E2E_EMPLOYEE_PASSWORD=
E2E_MANAGER_PASSWORD=
E2E_EMPLOYEE2_PASSWORD=
```

แล้วรันใหม่

```bash
npm run test:e2e
```

ไฟล์ `.env.local` ถูก gitignore ไว้ รหัสผ่านจึงไม่หลุดขึ้น GitHub
