## รายตัว

### ✅ เคสที่ 1 — ยื่นใบลาใหม่แล้วไปโผล่ในหน้ารายการ

`tests/e2e/01-submit-leave-request.spec.js` · 9 ขั้น · **US-02 + US-01** (+ US-10 เรื่องลำดับ)

ล็อกอินเป็น employee จดรายการเดิมไว้ กรอกฟอร์มยื่นใบลาใหม่ แล้วตรวจว่า
ใบนั้นโผล่ **บนสุด** ของตาราง มีป้าย "รอพิจารณา" ผู้ขอลาแสดงเป็นชื่อไทยไม่ใช่รหัส
คลิกเข้าไปแล้ว `id` ใน URL ตรง ค่าทุกช่องตรงกับที่กรอก มีวันเวลาที่ยื่นเกิดขึ้นเอง
และ **ยังอยู่ครบหลังกด F5 ทั้งหน้ารายละเอียดและหน้ารายการ**

### ✅ เคสที่ 2 — กดอนุมัติแล้วสถานะเปลี่ยนจริง

`tests/e2e/02-approve-leave-request.spec.js` · 8 ขั้น · **US-04**

ล็อกอินเป็น manager จด snapshot ทุกช่องไว้ กดอนุมัติ แล้วตรวจ 3 เรื่อง

1. **สถานะลง Firestore จริง** ไม่ใช่เปลี่ยนแค่บนหน้าจอ — พิสูจน์ด้วย F5 แล้วเปิดซ้ำจากแท็บที่สอง
2. **ปุ่มยังกดไม่ได้หลังโหลดหน้าใหม่** แยกเป็นขั้นต่างหากจากการเช็กสถานะ เพราะการปิดปุ่ม
   อาจเป็นแค่ผลของ event handler ตอนคลิก ถ้า logic ตอน render ไม่ได้เช็กด้วยจะกลับมากดซ้ำได้
3. **ช่องอื่นไม่ถูกเขียนทับ** เทียบ snapshot ก่อน–หลังทีละช่องแบบตัวอักษรต่อตัวอักษร

ปิดท้ายด้วยการล็อกอินเป็น employee เปิดใบลาของตัวเอง แล้วยืนยันว่าปุ่มอนุมัติ/ไม่อนุมัติกดไม่ได้

**ขอบเขต:** ครอบเฉพาะทาง "อนุมัติ" ไม่ได้ทดสอบทาง "ไม่อนุมัติ"
ถ้าจะครอบต้องใช้ใบลาอีกใบแยกต่างหาก แล้วรันชุดขั้นตอนเดียวกันโดยกด `#btn-reject` แทน

### ✅ เคสที่ 3 — เว้นช่องหัวข้อแล้วกดบันทึก

`tests/e2e/03-empty-title-validation.spec.js` · 6 ขั้น · **นอกเหนือเกณฑ์ที่สเปกเขียนไว้**

กรอกครบทุกช่องยกเว้นหัวข้อ แล้วกดบันทึก ต้องได้ 3 อย่าง

1. ขึ้นข้อความเตือนภาษาไทย
2. ยังอยู่หน้าเดิม ไม่เด้งไปหน้ารายการ
3. **จำนวนแถวในหน้ารายการเท่าเดิม** — ข้อนี้คือตัวจริงที่พิสูจน์ว่าไม่ได้บันทึก

เกณฑ์ US-02 ไม่ได้เขียนข้อนี้ไว้ แต่โค้ดตรวจให้อยู่แล้วที่ `js/new-leave-request.js:61`
เทสต์นี้จึงเป็นการล็อกพฤติกรรมที่มีอยู่ ไม่ให้หายไปตอนแก้โค้ดรอบหลัง

### ✅ เคสที่ 4 — คนที่ไม่ได้ล็อกอิน ต้องอ่านข้อมูลไม่ได้เลย

`tests/e2e/04-guest-cannot-read.spec.js` · 5 ขั้น · **US-08**

ตรวจ 2 ชั้น ชั้นแรกคือหน้าจอ (เปิด `leave-requests.html` และ `leave-request-detail.html`
ตรง ๆ ต้องถูกเด้งไป login ไม่มีข้อมูลโผล่) ชั้นที่สองคือ **ด่านจริง** — ยิงอ่าน
`leaveRequests` / `users` / `leaveTypes` ตรงไปที่ Firestore REST API ต้องได้ `PERMISSION_DENIED`

> 📌 เทสต์ตัวนี้เคย **ไม่ผ่าน** ตอนยังไม่ได้ Publish rules โดยติดที่ขั้น 4 — ยิงอ่านได้ `200 OK`
> ทั้งที่ไม่ได้ล็อกอิน หลัง Publish rules แล้วจึงกลับมาผ่าน แปลว่าเทสต์ตัวนี้จับของจริงได้

### ✅ เคสที่ 5 — เปิดใบลาของผู้ขอลาอีกคนไม่ได้

`tests/e2e/05-cannot-open-other-user-request.spec.js` · 6 ขั้น · **US-08**

ล็อกอินเป็น employee คนแรก หาใบลาของตัวเอง ออกจากระบบ ล็อกอินเป็น employee **อีกคน**
แล้วเปิด URL ใบของคนแรกตรง ๆ ตรวจ 3 ชั้น

1. หน้าจอต้องไม่แสดงหัวข้อใบลาของคนแรก
2. อ่านเอกสารใบลานั้นด้วย ID token ของคนที่สอง ต้องได้ `PERMISSION_DENIED`
3. อ่าน subcollection `approvals` ของใบนั้น ต้องถูกปฏิเสธด้วย

ใช้ manager หรือ hr เป็นคนที่สองไม่ได้ เพราะสองบทบาทนั้นเปิดใบลาทุกใบได้ตามการออกแบบ

## บั๊กที่เจอระหว่างทาง

### 🔴 dev server ทิ้ง query string (แก้แล้ว)

`serve` เปิด `cleanUrls` เป็นค่าเริ่มต้น เวลา redirect `/leave-request-detail.html?id=xxx`
ไปเป็น `/leave-request-detail` มัน **ทิ้ง `?id=xxx` ไปด้วย**

ผลคือบน `localhost:3000` คลิกแถวใบลาแล้วหน้ารายละเอียดไม่รู้ว่าต้องโหลดใบไหน — US-03 ใช้งานไม่ได้

```
localhost:3000/leave-request-detail.html?id=TESTID123
  → 301 Location: /leave-request-detail        ← id หายทั้งก้อน

sirikorn-cmru.github.io/.../leave-request-detail.html?id=TESTID123
  → 200 OK                                      ← ปกติ
```

โค้ดแอปไม่ได้ผิด บน GitHub Pages ทำงานถูกต้อง ปัญหาอยู่ที่ค่าเริ่มต้นของ dev server
**แก้แล้วด้วยการเพิ่ม `serve.json` ที่รากโปรเจกต์** ตั้ง `cleanUrls: false`

### ⚠️ ปุ่มอนุมัติ/ไม่อนุมัติ/ลบ กดได้ตอนหน้ากำลังโหลด (ยังไม่แก้)

ปุ่มทั้งสามใน `leave-request-detail.html` ไม่มี `disabled` ติดมาใน HTML ตั้งแต่แรก
JS เป็นคนปิดให้ตอน render ถ้าโหลดข้อมูลช้าหรือโหลดไม่สำเร็จ ผู้ใช้จะเห็นปุ่มกดได้อยู่ชั่วขณะ

**ไม่ใช่ช่องโหว่ความปลอดภัย** เพราะ Firestore Rules กันการเขียนไว้อีกชั้น (เคสที่ 5 พิสูจน์แล้ว)
เป็นเรื่อง UX แก้ได้ด้วยการใส่ `disabled` ใน HTML ตั้งแต่ต้น แล้วให้ JS เปิดทีหลัง
